# فلش‌کارت هماتولوژی

**مرور تصویری یافته‌های مورفولوژیک خون**

یک وب‌اپلیکیشن فارسی، واکنش‌گرا و کاملاً استاتیک برای دانشجویان علوم آزمایشگاهی و هماتولوژی. هر کارت یک تصویر واقعی از اسمیر خون محیطی را نشان می‌دهد؛ دانشجو ابتدا تصویر را بررسی می‌کند، سپس پاسخ و توضیح آموزشی آن را می‌بیند. حالت آزمون نیز تشخیص چشمی را با سه گزینه و بدون زمان و نمره تمرین می‌کند.

## امکانات

- **فلش‌کارت تصویری:** نمایش تصویر بدون نام، نمایش پاسخ با لمس تصویر یا دکمه، و پنهان‌کردن دوباره پاسخ.
- **توضیح آموزشی فارسی:** معرفی، ویژگی‌های کلیدی، نکته تشخیصی، نکته افتراقی و منابع برای هر یافته.
- **هایلایت پایدار:** ذخیره در `localStorage`؛ باقی‌ماندن پس از رفرش، بستن مرورگر و جابه‌جایی بین حالت‌ها.
- **فیلتر و جستجو:** مرور همه تصاویر یا فقط هایلایت‌شده‌ها، فیلتر دسته‌بندی و جستجوی انگلیسی/فارسی با تطبیق جزئی.
- **شمارنده کارت:** بر اساس مجموعه فعال (مثلاً «کارت ۳ از ۷» در حالت هایلایت‌شده‌ها) و با ارقام فارسی.
- **بزرگ‌نمایی حرفه‌ای:** نمایش تمام‌صفحه، زوم با دکمه/چرخ ماوس/پینچ، جابه‌جایی با درگ، بازنشانی و مقایسه تصویر پردازش‌شده با تصویر کامل اصلی.
- **آزمون تشخیص چشمی:** انتخاب تصادفی تصویر، سه گزینه یکتا و تصادفی، قفل گزینه‌ها پس از پاسخ، بازخورد درست/نادرست و توضیح آموزشی. بدون تایمر، درصد یا امتیاز.
- **تم روشن و تاریک:** انتخاب دستی، ذخیره‌سازی و استفاده از ترجیح سیستم در اولین بازدید، بدون پرش تم هنگام بارگذاری.
- **راست‌به‌چپ و فارسی‌محور:** فونت Shabnam به‌صورت محلی، ارقام فارسی، جداسازی دوسویه نام‌های انگلیسی با `<bdi>`.
- **دسترس‌پذیری:** پیمایش با کیبورد، نشانگر فوکوس، برچسب‌های ARIA، پشتیبانی از `prefers-reduced-motion` و اهداف لمسی مناسب.
- **بدون بک‌اند و بدون سرویس پولی:** کاملاً سازگار با GitHub Pages و بدون کلید API.

### میان‌برهای کیبورد (حالت فلش‌کارت)

| کلید | عملکرد |
| --- | --- |
| `Space` یا `Enter` | نمایش / پنهان‌کردن پاسخ |
| `→` | کارت قبلی |
| `←` | کارت بعدی |
| `H` | افزودن / حذف هایلایت |
| `Esc` | بستن نمایش تمام‌صفحه |

میان‌برها هنگام تایپ در ورودی‌ها غیرفعال می‌شوند.

## پیش‌نیازها و اجرای محلی

- Node.js نسخه ۲۲ یا جدیدتر
- npm
- Python نسخه ۳٫۱۰ یا جدیدتر (برای برش هوشمند تصاویر)

```bash
git clone <repository-url>
cd <project-folder>

npm install

# محیط مجازی پایتون (پیشنهادی)
python3 -m venv .venv
source .venv/bin/activate        # ویندوز: .venv\Scripts\activate
pip install -r requirements.txt

npm run dev
```

سایت روی آدرس نمایش‌داده‌شده توسط Vite (معمولاً `http://localhost:5173`) باز می‌شود.

> اگر Python یا OpenCV در دسترس نباشد، اسکریپت کاتالوگ همچنان کار می‌کند و تصاویر را **بدون برش** کپی می‌کند؛ در این حالت هشداری در ترمینال و در گزارش‌ها ثبت می‌شود. برای کیفیت نهایی و انتشار، نصب وابستگی‌های پایتون توصیه می‌شود.

## افزودن تصویر جدید

۱. فایل‌های تصویر را داخل پوشه `input/` قرار دهید. پوشه‌های تودرتو هم پشتیبانی می‌شوند:

```text
input/
├── Howell jolly body.jpg
├── Bite cell⁄Blister cell.png
└── مجموعه دوم/
    └── Sickle cell⁄Drepanocyte.webp
```

۲. کاتالوگ را بازسازی کنید:

```bash
npm run generate:data
```

۳. برای دیدن تغییرات:

```bash
npm run dev
```

برای انتشار خودکار، کافی است فایل‌ها را commit و push کنید؛ GitHub Actions بقیه کارها را انجام می‌دهد:

```text
افزودن تصویر به input/
        ↓
commit و push
        ↓
GitHub Actions: پردازش تصاویر + ساخت کاتالوگ + build
        ↓
به‌روزرسانی خودکار GitHub Pages
```

هیچ نیازی به ویرایش دستی آرایه کارت‌ها، فهرست تصاویر یا اجرای دستی دستور انتشار نیست.

### قالب‌های پشتیبانی‌شده

`JPG`، `JPEG`، `PNG`، `WEBP` و `AVIF`.

قالب‌هایی مانند `HEIC/HEIF` (عکس آیفون)، `TIFF`، `BMP` و `GIF` پشتیبانی نمی‌شوند و در گزارش با پیام راهنما فهرست می‌شوند. آن‌ها را قبل از افزودن به JPG یا PNG تبدیل کنید. فایل‌های ناشناخته نادیده گرفته می‌شوند و باعث خطای build نمی‌شوند.

### نام فایل، عنوان کارت و شناسه پایدار

- عنوان کارت دقیقاً **نام فایل بدون پسوند** است؛ شامل حروف بزرگ و کوچک، فاصله‌ها، علائم و کاراکترهای خاص.
  - `Hb H disease.jpg` → `Hb H disease`
  - `Bite cell⁄Blister cell.png` → `Bite cell⁄Blister cell`
- نام‌های انگلیسی ترجمه نمی‌شوند و کاراکترهایی مانند `⁄` (U+2044) تغییر نمی‌کنند.
- شناسه هر کارت از **مسیر نسبی فایل** و یک هش پایدار ساخته می‌شود، نه از شماره ردیف. بنابراین افزودن یا حذف تصاویر دیگر، شناسه کارت‌های موجود را تغییر نمی‌دهد و هایلایت‌ها حفظ می‌شوند.
- دو فایل هم‌نام در پوشه‌های مختلف، دو کارت مستقل با شناسه‌های یکتا می‌شوند.
- کاتالوگ هر بار از صفر ساخته می‌شود؛ کارت تکراری ایجاد نمی‌شود.

## پردازش خودکار تصویر میکروسکوپ

بسیاری از تصاویر، عکس موبایل از چشمی میکروسکوپ‌اند: یک میدان روشن دایره‌ای در میان بدنه تاریک میکروسکوپ یا پس‌زمینه اتاق. `scripts/process-images.py` این میدان را پیدا و برش می‌دهد:

۱. اصلاح جهت EXIF (برای عکس‌های موبایل).
۲. کوچک‌کردن برای تحلیل سریع.
۳. تولید کاندیدهای مرکز دایره با آستانه‌گذاری Otsu، کانتور، تبدیل فاصله و تشخیص دایره Hough.
۴. نمونه‌برداری شعاعی از روشنایی و یافتن لبه واقعی میدان در ۲۴۰ زاویه.
۵. برازش دایره با کمترین مربعات، حذف نقاط پرت و محاسبه اطمینان بر اساس:
   - نسبت زوایای دارای لبه معتبر
   - پیوستگی شعاع لبه
   - پرشدگی روشنایی داخل دایره
   - کنتراست داخل و بیرون
   - نسبت شعاع به ابعاد تصویر
۶. برش مربع با حاشیه اطمینان ۹٪ و ماسک دایره‌ای با لبه نرم و پسوند شفاف.
۷. خروجی WebP با کیفیت ۹۰ و حداکثر ضلع ۱۴۰۰ پیکسل.

**در صورت اطمینان ناکافی، هیچ برش تهاجمی انجام نمی‌شود:** تصویر اصلی حفظ و با حالت `contain` نمایش داده می‌شود، در گزارش به‌عنوان «نیازمند بازبینی» ثبت می‌شود و در کارت نشان هشدار نمایش می‌یابد. فایل‌های اصلی `input/` هرگز تغییر نمی‌کنند.

**تصویر کامل:** در هر کارت، دکمه «مشاهده تصویر کامل» و در نمایشگر تمام‌صفحه، کلید تعویض «تصویر پردازش‌شده / تصویر کامل» وجود دارد. تصویر پردازش‌شده پیش‌فرض است.

خروجی‌ها:

- `public/cards/` → تصاویر بهینه‌شده (دایره‌ای با شفافیت یا `contain`)
- `public/originals/` → نسخه کامل و بدون تغییر فایل اصلی برای بررسی زمینه
- `src/generated/catalog.json` → کاتالوگ مصرفی برنامه

نسخه‌های پردازش‌شده با کلید اندازه و زمان تغییر فایل در `.cache/image-processing.json` نگه‌داری می‌شوند تا اجرای دوباره سریع باشد.

## توضیحات آموزشی

توضیحات علمی به‌صورت **جدا از کاتالوگ تولیدشده** در این فایل نگه‌داری می‌شوند:

```text
src/data/descriptions.fa.json
```

بنابراین بازسازی کاتالوگ هرگز محتوای دست‌نویس را از بین نمی‌برد. دسته‌بندی‌ها نیز در `src/data/categories.fa.json` تعریف شده‌اند.

### ساختار هر توضیح

```json
{
  "howell-jolly-body": {
    "nameFa": "جسم هاول-جولی",
    "summary": "معرفی کوتاه و دقیق یافته.",
    "keyFeatures": ["ویژگی اول", "ویژگی دوم", "ویژگی سوم"],
    "diagnosticSignificance": "نکته تشخیصی.",
    "differentialDiagnosis": "نکته افتراقی.",
    "categories": ["inclusions"],
    "tags": ["Howell-Jolly", "hyposplenia"],
    "sources": [
      {
        "title": "عنوان واقعی منبع",
        "url": "https://example.org/reference"
      }
    ],
    "needsReview": false
  }
}
```

- کلید هر ورودی از **نام فایل** ساخته می‌شود: حروف کوچک، حذف علائم ترکیبی، تبدیل کاراکترهای غیرحرفی به خط تیره.
  - `Howell jolly body.jpg` → `howell-jolly-body`
  - `Bite cell⁄Blister cell.jpg` → `bite-cell-blister-cell`
- `needsReview: true` برای یافته‌های نامطمئن یا غیراستاندارد، هشدار بازبینی در کارت نمایش می‌دهد.
- عنوان و نشانی منابع باید واقعی باشند؛ منبع ساختگی وارد نکنید.
- اگر توضیحی برای تصویر جدید وجود نداشته باشد، **کارت همچنان نمایش داده می‌شود** و پیام «توضیح آموزشی هنوز ثبت نشده است» دیده می‌شود. فهرست این تصاویر در ترمینال و `reports/catalog-report.json` می‌آید.
- برنامه هیچ توضیح پزشکی را از روی نام فایل حدس نمی‌زند و از API هوش مصنوعی استفاده نمی‌کند.

### افزودن توضیح برای تصویر جدید

۱. نام فایل را به کلید توضیح تبدیل کنید (قواعد بالا).
۲. یک ورودی با همان کلید در `descriptions.fa.json` اضافه کنید.
۳. `npm run validate:content` را اجرا کنید تا ساختار، دسته‌بندی‌ها و منابع بررسی شوند.
۴. کاتالوگ را بازسازی کنید.

## انتشار خودکار در GitHub Pages

### تنظیم یک‌باره مخزن

۱. مخزن را در GitHub بسازید و پروژه را push کنید.
۲. به **Settings → Pages** بروید.
۳. در بخش **Build and deployment**، گزینه **Source** را روی **GitHub Actions** بگذارید.
۴. تمام. هیچ Secret، توکن شخصی، سرور یا سرویس اضافی لازم نیست.

از این پس، هر push روی شاخه انتشار، workflow را اجرا می‌کند:

```text
.github/workflows/deploy.yml
```

مراحل workflow:

۱. نصب Node و Python و وابستگی‌ها
۲. `npm run build` → پردازش تصاویر، ساخت کاتالوگ، بررسی TypeScript و build ویت
۳. اعتبارسنجی محتوا
۴. آپلود گزارش پردازش تصویر به‌عنوان Artifact
۵. آپلود خروجی `dist/` و انتشار با `actions/deploy-pages`

اجرای دستی نیز از تب **Actions → Deploy to GitHub Pages → Run workflow** ممکن است (`workflow_dispatch`).

> **شاخه انتشار:** این workflow برای هر دو نام رایج `main` و `master` آماده است. اگر نام شاخه پیش‌فرض مخزن شما متفاوت است، آن را در بخش `on.push.branches` فایل `deploy.yml` جایگزین کنید.

مسیر base در `vite.config.ts` برابر `./` است؛ بنابراین سایت هم در آدرس پروژه‌ای (`https://user.github.io/repo/`) و هم در دامنه ریشه کار می‌کند.

## گزارش‌ها و بررسی کیفیت برش

پس از اجرای `npm run generate:data` یا `npm run build`:

- `reports/image-review.html` → **گزارش بصری HTML** شامل تصویر اصلی در کنار برش پردازش‌شده، اطمینان، روش تشخیص و هشدارها. برای بررسی سریع خطاهای برش، این فایل را در مرورگر باز کنید.
- `reports/image-processing.json` → خروجی خام پردازش (مرکز، شعاع، اطمینان، وضعیت).
- `reports/catalog-report.json` → خلاصه کاتالوگ، تصاویر بدون توضیح، قالب‌های پشتیبانی‌نشده و توضیحات بدون تصویر.

در GitHub Actions، پوشه `reports/` به‌عنوان Artifact با نام `image-processing-report` ذخیره می‌شود و از صفحه اجرای workflow قابل دانلود است.

اعداد خلاصه در ترمینال شامل تعداد تصاویر کشف‌شده، برش دایره‌ای، موارد نیازمند بازبینی، توضیحات موجود، توضیحات غایب و فایل‌های پشتیبانی‌نشده است.

## عیب‌یابی

| مشکل | راه‌حل |
| --- | --- |
| تصویر جدید در سایت نیست | مطمئن شوید فایل داخل `input/` است، پسوندش پشتیبانی می‌شود و `npm run generate:data` اجرا شده است. سپس `src/generated/catalog.json` و `public/cards/` را commit کنید یا تغییر را push کنید. |
| در GitHub Pages چیزی تغییر نکرد | در تب Actions بررسی کنید workflow با موفقیت اجرا شده باشد و در Settings → Pages منبع روی GitHub Actions باشد. |
| تصویر برش نمی‌خورد | Python/OpenCV نصب نیست یا تشخیص با اطمینان کافی ممکن نشده است. `pip install -r requirements.txt` را اجرا کنید و گزارش `reports/image-review.html` را ببینید. |
| برش اشتباه است | تصویر کامل همیشه از داخل برنامه و از مسیر `public/originals/` قابل مشاهده است. الگوریتم در موارد نامطمئن خودکار به حالت بدون برش برمی‌گردد؛ اگر برشی با اطمینان بالا اما نادرست بود، گزارش را بررسی و آستانه‌های `scripts/process-images.py` را تنظیم کنید. |
| توضیح کارت نمایش داده نمی‌شود | کلید توضیح با نام فایل هم‌خوان نیست. `npm run validate:content` و بخش «توضیحات بدون تصویر» در `reports/catalog-report.json` را ببینید. |
| قالب HEIC/HEIF پذیرفته نمی‌شود | آن را به JPG یا PNG تبدیل کنید (مثلاً با تنظیمات دوربین آیفون یا ابزار تبدیل تصویر). |
| تصویر AVIF پردازش نشد | پشتیبانی AVIF به نسخه Pillow/OpenCV وابسته است؛ فایل به‌صورت اصلی و بدون برش نمایش داده می‌شود. تبدیل به WebP نتیجه بهتری می‌دهد. |
| فونت یا آیکون‌ها بارگذاری نمی‌شوند | فونت‌ها محلی‌اند و نیازی به CDN ندارند. بررسی کنید فایل‌های `src/styles/fonts/*.woff2` در مخزن باشند. |
| ارقام فارسی نیستند | شمارنده‌ها و شمارش‌ها با `Intl.NumberFormat("fa-IR")` قالب‌بندی می‌شوند. نام فایل‌های انگلیسی عمداً تغییر نمی‌کنند. |
| هایلایت‌ها از بین رفته‌اند | هایلایت در `localStorage` همان مرورگر ذخیره می‌شود؛ حالت ناشناس، پاک‌کردن داده سایت یا مرورگر دیگر آن را نشان نمی‌دهد. حساب کاربری و همگام‌سازی ابری وجود ندارد. |

---

## محدودیت‌ها

- **توضیح خودکار برای تصاویر آینده وجود ندارد.** تولید متن پزشکی معتبر بدون بازبینی انسانی و بدون سرویس هوش مصنوعی/بک‌اند انجام نمی‌شود؛ بنابراین تصاویر جدید بدون توضیح نمایش داده می‌شوند تا زمانی که متن آن‌ها افزوده شود. این رفتار عمدی و ایمن است.
- قالب‌های HEIC/HEIF، TIFF، BMP و GIF پشتیبانی نمی‌شوند و باید تبدیل شوند.
- تصویر «Blurred cell» در منابع استاندارد یک یافته مورفولوژیک مستقل نیست؛ توضیح آن با علامت «نیازمند بازبینی» و با احتیاط نوشته شده است.
- برش خودکار بر پایه بینایی ماشین است و ممکن است در عکس‌های بسیار نامتعارف (میدان دایره‌ای شدیداً ناقص، انعکاس شدید، فوکوس بسیار ضعیف) به بازبینی نیاز داشته باشد. تصویر اصلی همیشه حفظ و قابل مشاهده است.
- برنامه حساب کاربری، همگام‌سازی ابری یا بک‌اند ندارد؛ هایلایت‌ها فقط در همان مرورگر می‌مانند.
- تنظیمات GitHub Pages باید یک‌بار به‌صورت دستی روی GitHub Actions قرار گیرد.
- هیچ تایمر، درصد پاسخ صحیح، جدول امتیاز یا گیمیفیکیشن در آزمون وجود ندارد (مطابق طراحی آموزشی).
